# BUILD312 — تصحيح فحص ملفات Runtime الأصلي

المرجع BUILD311: af4350085117ed7ab4bb1b9c4749d98d823d9ed5.

أرسل المالك صورة فشل تثبيت التحديث برسالة `Runtime file set differs from its manifest.`. حزمة BUILD311 نفسها تضم 84 ملفًا مطابقًا لقائمة Runtime، وقد اجتازت المطابقة والتوقيع واختبارات الويب؛ هذه الاختبارات لم تنفذ تعداد ملفات Sandbox الأصلي على الآيفون.

اكتُشف اختلاف حقيقي بين فحصين في GlobalGameStorage.swift: فحص Exact Snapshot يستخدم safeRelativePath مع معالجة المسارات المكافئة، بينما فحص Runtime manifest يقصّ entry.path اعتمادًا على طول folder.path. عند اختلاف مساري الأصل والنتيجة بسبب alias مثل /var و/private/var، ينتج اسم نسبي خاطئ وتفشل مقارنة المجموعتين. صورة المستخدم وحدها لا تكشف أسماء الملفات المخالفة؛ لذلك يضيف الإصلاح أيضًا أسماء الملفات المفقودة والزائدة إلى رسالة الخطأ.

يوحد الإصلاح التعداد في runtimeFilePaths: يطبّع مجلد الجذر ويحل أسماءه المكافئة، ويفحص احتواء كل مسار، ويرفض symlinks داخل Runtime، ويحافظ على التطابق الكامل. تُدرج الملفات المخفية في كلا الفحصين؛ لا يجري تجاهل ملف زائد للتحايل على المطابقة. لا تتغير التواقيع أو hashes أو شروط المخطط أو حدود معاملة التحديث.

يضيف scripts/test_native_runtime_paths.py اختبار Foundation حقيقيًا على macOS؛ يستخرج طرق الإنتاج من Swift نفسها ويختبر أصلًا باسم مكافئ وطفلًا بمسار حقيقي، والمجلدات المتداخلة والشرطة الختامية، وخروج المسار عن الجذر، وملفًا زائدًا مخفيًا، وملفًا ناقصًا، ورابطًا رمزيًا داخل Runtime، ثم كل ملفات WebApp. يُشغّل داخل CI مع بوابة Swift، بالإضافة إلى حارس المصدر.

هذا إصلاح Native ويتطلب IPA BUILD312. إرسال حزمة Web جديدة إلى المثبّت المعيب لا يبدل منطق Swift. يحتوي IPA على تشغيل اللوجستيات BUILD311 مع هوية Runtime 312، والمفتاح العام نفسه gh-primary-2026-build310، وSave Schema 2.0.0. لا تعديل للسرعات أو تشغيل الشركات أو الاقتصاد أو بيانات اللاعب.

التثبيت المقصود فوق التطبيق الموجود بنفس هوية التطبيق وطريقة التوقيع مع الاحتفاظ بالحفظ، دون حذف التطبيق. نجاح CI ليس اختبار آيفون فعليًا؛ إذا تكرر الرفض، تعرض الرسالة الجديدة الفرق المحدد لتشخيص سبب إضافي بدل افتراض التطابق.
