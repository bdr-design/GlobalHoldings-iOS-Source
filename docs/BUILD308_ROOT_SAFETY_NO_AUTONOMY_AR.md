# BUILD308 — إصلاح جذري للحركة والمسارات والحماية

## النتيجة

يعالج هذا البناء جذور المشكلات من دون تغيير ملكية الزمن أو Save Schema:

- الحركة المنطقية تبقى دقيقة وفق زمن المحاكاة، لكن العلامة المرئية تتحرك بسرعة بشرية ثابتة ولا تقفز عند `600×`.
- لكل أصل مسار حصري تابع لشركته ونوعه؛ يُرفض المسار المكرر أو المعكوس أو القريب هندسيًا.
- زر المغادرة الجماعية لا يكرر المسارات، ولا ينفذ نصف الدفعة ثم يترك الباقي.
- لا توجد وحدة أو واجهة أو سلطة تشغيل ذاتي في Runtime.
- كل أصل مشتَرى يحصل تلقائيًا على العدد الثابت نفسه من الطاقم داخل معاملة التسليم.
- فشل أصل واحد يعزله وحده، بينما أعطال سلامة الحفظ والزمن فقط تستطيع إيقاف اللعبة كاملة.

## أسباب الخلل التي عولجت

| الجذر | الأثر السابق | الإغلاق في BUILD308 |
|---|---|---|
| ربط موضع العلامة مباشرة بقفزة تقدم المحاكاة | الأصل يقفز بسرعة غير قابلة للمتابعة عند مضاعفات الزمن | متابع عرض مستقل محدود بالبكسل/ثانية، لا يغير الحالة |
| أكثر من واجهة لإسناد المسار | خيارات متعارضة ومسار منفصل لا ينسجم مع الشركات | مركز مسارات واحد ومالك مجال واحد |
| اعتبار اختلاف المعرّف كافيًا | مساران بمعرفين مختلفين قد يكونان الممر نفسه | بصمة هندسية + مقارنة ممر بعد أخذ عينات متساوية المسافة |
| تنفيذ دفعة على الحالة الحية | خطر حركة أو حفظ جزئي إذا فشل أصل متأخر | نسخة Draft كاملة، تحقق شامل، Commit متين، ثم استبدال الحالة الحية |
| كتابة المتصفح قبل معرفة نتيجة Native | احتمال اختلاف نسختين عند رفض الإقرار أو ضياعه | Rollback عند الرفض، وقفل توفيق عند انتهاء المهلة |
| سجلات وكاش بلا حدود صارمة | نمو الحفظ تدريجيًا حتى فشل الكتابة أو بطء اللعبة | سقوف ثابتة وتقليص حتمي مع الحفاظ على أحدث الأدلة |
| تصعيد خطأ أصل إلى عطل محاكاة عام | أصل سيئ قد يوقف كل الشركات | Fault domain مستقل لكل أصل |

## عقد الحركة المرئية

طبقة العرض تقرأ آخر حالة ملتزمة فقط ولا تكتب فيها. السقوف هي:

| سرعة المحاكاة | السقف المرئي |
|---:|---:|
| `30×` | `28px/s` |
| `60×` | `30px/s` |
| `120×` | `32px/s` |
| `300×` | `34px/s` |
| `600×` | `36px/s` |

تُقص كل خطوة زمنية مرئية عند `50ms`، فلا تنتج قفزة ضخمة بعد إطار متأخر. عند تغيير المسار، أو عودة التطبيق من الخلفية، أو تحريك الخريطة، تُعاد مزامنة العلامة بتلاشي قصير بدل Tween سريع. المسار المرئي يتبع هندسة الطريق/الممر نفسها، بما فيها الاتجاه العكسي.

## عقد المسار

`route-core.js` هو المالك الوحيد للإنشاء والاستبدال والحذف والكاش والنهايات. يرفض:

1. معرف مسار مكرر.
2. هندسة مطابقة في الاتجاه نفسه أو العكسي.
3. ممرًا قريبًا بعد `33` عينة إذا كان اختلاف الطول لا يتجاوز `4%`، والنهايات ضمن `2.5km`، ومتوسط الانحراف ضمن `1.25km`، وأقصاه ضمن `3km`.
4. مسارًا لا يطابق `company === type`.
5. أكثر من `240` مسارًا، أو `360` نهاية، أو `160` سجل كاش، أو `2048` نقطة للمسار.
6. إسناد المسار نفسه أو ممر قريب منه لأصل ثانٍ.

الاستبدال مسموح عند بلوغ السقف فقط إذا كان المسار القديم حصريًا للأصل نفسه. وبعد الحذف تُزال نهايات المسار العامة التي لم يعد يستخدمها مسار أو أصل.

## المغادرة الجماعية لمسارات مختلفة

الأمر يعمل داخل شركة واحدة فقط:

- `AIR` و`SEA`: تُرتب الأصول المتاحة حتميًا، ويُبنى لكل أصل ممر إلى وجهة عالمية ضمن مداه، ثم يُفحص ضد جميع المسارات التي اختيرت قبله. المسار القديم الحصري يُستبدل بدل تراكم مسارات مهجورة.
- `ROAD`: لا تُنشأ طرق افتراضية. تُوزع الشاحنات على مسارات موجودة تبدأ من مراكزها، مع حجز حصري وفحص عدم التقارب. إذا لم تكفِ المسارات، يلغى الأمر كله ويوضح السبب.

تسلسل الأمر هو: Clone للحالة، اختيار كل المسارات، فحص الطاقم والموقع والمدى والحصرية، إسناد الجميع، مغادرة الجميع، فحص Save Schema والسلامة، كتابة المتصفح، انتظار إقرار Native، ثم استبدال الحالة الحية. أي استثناء قبل النهاية يلغي الـDraft كله.

## الطرق اللوجستية

حُذف إسقاط نقطة حرة على الخريطة. إنشاء الطريق يتطلب:

- مركز انطلاق ومركز وصول مختلفين.
- ملكية المركزين لشركة اللوجستيات.
- نجاح مزود الطريق في إرجاع هندسة شارع فعلية.
- مرور الهندسة على Route Core وعدم تعارضها مع ممر قائم.
- نجاح الحفظ المتين قبل ظهور المسار كحالة حية.

فشل الشبكة لا يرسم خطًا مستقيمًا بديلًا ولا ينشئ سجلًا ناقصًا؛ يبقى كل شيء كما كان.

## الطاقم الثابت المحفوظ

| الأصل | التوزيع الثابت | الإجمالي |
|---|---|---:|
| طائرة | 4 طيارين + 6 ضيافة + 2 مهندسين | 12 |
| سفينة | 2 قبطان + 14 بحارًا/ملاحًا + 4 مهندسين | 20 |
| شاحنة | 2 سائقين + 1 فني صيانة | 3 |

عند إثبات التسليم ينشئ Fleet Core سجل الطاقم والعقد الدائم والراتب ويربطها بمعرف الأصل. العملية idempotent: إعادة المصالحة لا تنشئ عقدًا ثانيًا. بيع الأصل أو إعادة المؤجر ينهي العقد ويعيد حساب إجماليات الطاقم. إذا تعذر إثبات طاقم أي أصل في شراء متعدد، ترجع معاملة الشراء كاملة.

## حدود الفشل ومنع التراكم

- خطأ حساب أصل: يوضع `ASSET_SIMULATION_ISOLATED` على ذلك الأصل، ويمنع تشغيله فقط إلى أن يُصان أو يعاد إسناد مساره.
- خطأ واجهة/خريطة غير حرج: يسجل ولا يوقف الزمن.
- حمل إطار مرتفع: يخفض حاكم الأداء سرعة المحاكاة ويسقط backlog بدل مطاردته.
- فشل كتابة أو Schema: لا يعتمد التغيير.
- رفض Native: تعاد آخر لقطة متصفح مكتملة.
- انتهاء مهلة الإقرار: تُقفل الكتابة وتُعاد الواجهة من خزنة Native للتوفيق؛ لا يُفترض أن الطلب فشل أو نجح.
- الإيقاف العام محصور في كسر سلسلة سجل التحكم، فساد Save Schema، رجوع معاملة فاشل، عدم رتابة الزمن، أو فشل استعادة Native.

## تطوير الأقسام المنفذ

| القسم | التطوير |
|---|---|
| التشغيل والأصول | سجل أصول مملوكة، متجر منفصل، مركز مسارات موحد، فلاتر قطاعية، أسباب تعطيل واضحة |
| القيادة | مركز مهام للاستثناءات وسجل تنفيذ للمراجعة؛ لا طوابير أو سلطة تنفيذ ثانية |
| الشركات | منشآت وأصول ونتيجة مالية مستقلة لكل شركة |
| الموارد البشرية | وظائف المنشآت والقيادات فقط؛ طاقم الأصل ملك Fleet Core لمنع الازدواج |
| المالية | قيد متوازن، مستند دفع، وميزانية شركة قبل اعتماد العملية |
| الحوكمة | مراجعة وأدلة وحوادث، من دون تنفيذ عمليات الشركات |
| النظام | صحة، تشخيص، حفظ، تحديث واستعادة؛ الأعطال المحلية لا تتحول إلى توقف شامل |

## اختبارات القبول

- اختبار Route Core للمطابق والمعكوس والقريب وعزل الشركة والسعة والاستبدال عند الامتلاء.
- اختبار شراء أصلين وإثبات `24` وظيفة طاقم ثابتة من دون عقد مكرر.
- اختبار متصفح كامل يشتري طائرتين، ويرسلهما بزر واحد، ويتأكد من معرفين وممرين غير متقاربين، ثم يحفظ ويعيد التحميل ويقارن الحالة.
- اختبار ACK ناجح، وNACK مع Rollback، وانتهاء مهلة مع قفل التوفيق.
- اختبار الحركة عند جدول رسم `10fps`: لا قفزة، لا خطأ متصفح، ولا اختلاف في زمن المحاكاة.
- فحص جميع لوحات iPhone الأفقي والعمودي، وفحص ملكية المجالات، وAST، وRuntime/Native contracts، وسلامة حزمة المصدر.

## مراجع القرار الهندسي

- مواصفة Web Storage تنص على أن السكربتات لا يمكنها افتراض قفل مشترك للتخزين، وتحدد فشل `setItem()` عند تعذر الكتابة؛ لذلك لا يُعامل `localStorage` وحده كمعاملة موزعة: <https://html.spec.whatwg.org/multipage/webstorage.html>
- واجهات WebKit الرسمية الخاصة بالرسائل ذات الرد وتنفيذ JavaScript غير المتزامن هي أساس فصل إقرار Native عن كتابة واجهة الويب: <https://developer.apple.com/documentation/webkit/wkscriptmessagehandlerwithreply> و<https://developer.apple.com/documentation/webkit/wkwebview/callasyncjavascript(_:arguments:in:in:completionhandler:)>
- الإصدار المستقر المضمّن لمحرك الخريطة هو Leaflet `1.9.4` كما تعرضه صفحة المشروع الرسمية: <https://leafletjs.com/download.html>

هذه المراجع توجه حدود الحفظ والجسر ومحرك الخريطة، أما قواعد اللعبة والأعداد والذرية فمملوكة لاختبارات المشروع نفسها.
