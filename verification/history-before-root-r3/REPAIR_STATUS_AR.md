# Global Holdings — Build 334 المصحح: الشركات التابعة والموارد البشرية

## نطاق النسخة

اجتاز المصدر المصحح بوابة القبول الأصلية كاملة: 12 مجموعة اختبارات، دون حذف مرحلة أو تخفيف شرط حماية. مصفوفة القبول أنتجتها `tools/run_acceptance.py` تلقائيًا. رقم تشغيلها:
`c4599d5eb480245c45613dd001b3616c63fb822caf35054663939803b2702884`

هذا مصدر كامل نظيف للإصدار 3.0.0 / Build 334، وليس تحديث Overlay. Save Schema باقٍ 2.0.0. ملف IPA النهائي يُعتمد فقط مع نجاح فاحص الحزمة وفاحص أرشيفات التسليم، ويظل غير موقّع. نتيجة التغليف موجودة في `verification/334-package-verification.json` وملف `GlobalHoldings_BUILD334_RELEASE.json` المصاحب للتسليم. التوقيع والتثبيت وWKWebView على iPhone فعلي لم تُختبر في هذه الجلسة.

## إصلاحا السبب الجذري

1. مولّد `tabs()` داخل `WebApp/advanced-core.js` كان يستبدل سمتي `data-companytab` و`data-labortab` بسمة لا تلتقطها معالجات النقر الأصلية. أضيفتا إلى سجل السماح الدقيق، مع بقاء ترميز المدخلات ورفض السمات غير المعروفة. لا يوجد مستمع نقر موازٍ.
2. بعد إصلاح النقر، كشف اختبار التطبيق الكامل أن عرض قائمة الشركات يستدعي `companyPerformance` لشركة كتالوج لم تُؤسَّس بعد، فتفشل المالية مغلقًا برسالة `company-not-found:air`. صُحّح مالك عرض القائمة نفسه: طلب أداء الشركة لا يحدث إلا لنسخة مفتوحة وتشغيلية لديها القدرة المركزية `finance.book`. لم يُخفَّف رفض الشركات المجهولة، ولم يُنشأ حساب وهمي، ولم يتغير أي مالك للمال أو الوقت.

أعيد تشغيل النقر واللمس الحقيقيين طوليًا وعرضيًا: الشركات التابعة و6 تبويبات موارد بشرية، الوصول لمدخل التأسيس، حفظ تبويب الشركات واستعادته بعد التحميل، وغياب تغييرات المال والملكية والموظفين والتخصيصات أثناء التنقل. اختبار المكوّن الأصلي نجح 16/16. أضيف اختبار عقد يمنع الاستعلام المالي عن شركة غير مؤسسة أو معلقة أو بلا قدرة دفتر مالي.

## سلسلة المصدر

البدء من `GlobalHoldings_BUILD334_Source_HANDOFF.zip` ببصمة `d4af68b03ba87ce5c078d4aeb24596367584fc4dae48ae85271b76379d503abd` وحجم 86,434,500 بايت. حزمة إصلاح الجلسة السابقة أعادت تكوين المصدر في مجلد جديد مع تحقق كل ملف، وحافظت على فروق الإغلاق الأربعة التي كانت موجودة في IPA المستخدم النهائي (app.js، company-definitions.js، conference-3d.js، finance-core.js).

مقارنة المصدر المصحح مع IPA المستخدم النهائي ذي البصمة `4c8fe3aac39dbef5ca7ad315459f11bdfb7210b985bc66713040c872230cbc7e`: 467 ملف تشغيل من 468 مطابق؛ الاختلاف الجديد الوحيد هو `advanced-core.js`. لا تغيير جديد في CSS أو الهوية أو محرك الوقت أو التوقيع أو الحفظ أو الملفات Native. المصدر المرجعي الكامل Build 333 فُحص: 572 ملفًا دون اختلاف عن أرشيفه. كل المرفقات الأصلية بقيت ببصماتها وأحجامها.

## بيئة التنفيذ ومعالجة العوائق

Node 24.20.0، Playwright 1.55.1، Chromium headless shell 140.0.7339.186، ESLint 10.10.0 والتبعيات المحددة في package.json. جُهزت الأدوات العامة فقط على فرع GitHub مستقل `build334-verification-toolchain-20260920` (تشغيل 35528822872)، دون رفع مصدر اللعبة أو مفاتيحها ودون تعديل main. أزيل متغير DISPLAY القديم من بيئة تشغيل الاختبارات لأنه يشير إلى شاشة X غير موجودة؛ لم تتغير سياسة متصفح أو إعداد أمان في اللعبة. عمل localhost وWebGL الفعلي بواسطة متصفح Playwright الرسمي ومكتباته.

## تصحيح الاختبارات المثبت بالأدلة

- اختبار الترقية كان يمرر 2 إلى `page.evaluate` بدل `assert.equal`، فيقارن السرعة الفعلية الصحيحة 2 بنص رسالة الخطأ. صحح موضع القوس فقط، وبقي المطلوب استئناف السرعة 2.
- بعد إثبات الاستئناف 2، يُضغط زر الإيقاف الحقيقي قبل اختبارات التقويم والحسابات التي تتطلب حالة متوقفة. لم يُغيّر سلوك إلغاء التقدم الزمني في التطبيق؛ مالكه مطابق لـ333. بقيت توقعات التقويم الأصلية كما هي.
- قوِّي اختبار الترقية بفشلين متتاليين في الحفظ الدائم للتوقيع: لا ختم أو تفويض جزئي، لا تغيير revision أو بيانات الأعمال، السرعة تبقى 0، ثم نجاح ذري واستئناف 2. التأكد من عدم فتح نافذة التفويض مجددًا بعد إعادة التحميل مثبت أيضًا. لم يحقن الاختبار توقيعًا في حفظ 333 ولم يفتح نافذة الترقية يدويًا.
- أُدرج اختبارا التبويبات الكامل والمعزول كذلك ضمن npm test امتثالًا لتغطية فاحص الحزمة الأصلي؛ بقيا ضمن test:interface. لم يُعدّل فاحص التغطية أو قائمة بوابات القبول أو آلية التغليف.
- بعد اجتياز القبول وفحص IPA، كشف فاحص الأرشيف مقارنة خاطئة بين build=334 العددي في تقرير JSON وBUILD="334" النصي المخصص لـInfo.plist. صحح `verify_release_archives.py` حد JSON بدالة تتحقق من النوع الصحيح والرقم الصحيح معًا، وترفض الأرقام الخاطئة والنصوص وfloat وbool والقيم المفقودة. اختباران جديدان يثبتان القبول الصحيح والرفض؛ رقم البناء في بيان الإصدار JSON صار integer مطابقًا للتقرير، بينما Info.plist يبقى كما هو. لم تتغير أي ملفات WebApp بسبب هذا التصحيح.

## إعادة التنفيذ

من جذر المصدر وبالتبعيات المحددة:

```sh
export PYTHONDONTWRITEBYTECODE=1
# في بيئة بلا شاشة X فعلية فقط، احذف DISPLAY القديم قبل اختبارات headless.
python3 tools/run_acceptance.py --previous-source /absolute/path/GlobalHoldings_BUILD333_Source
python3 tools/set_build_metadata.py
python3 tools/repack_ipa.py --base /absolute/path/GlobalHoldings_v3_0_0_build333_unsigned.ipa --output /fresh/output/GlobalHoldings_v3_0_0_build334_unsigned.ipa
python3 tools/verify_build334.py --base /absolute/path/GlobalHoldings_v3_0_0_build333_unsigned.ipa --ipa /fresh/output/GlobalHoldings_v3_0_0_build334_unsigned.ipa --baseline verification/333-source-manifest.sha256
python3 tools/build_release_archives.py --output-dir /fresh/output
python3 tools/verify_release_archives.py --ipa /fresh/output/GlobalHoldings_v3_0_0_build334_unsigned.ipa --source-zip /fresh/output/GlobalHoldings_BUILD334_Source.zip --verification-zip /fresh/output/GlobalHoldings_BUILD334_Verification.zip --release-manifest /fresh/output/GlobalHoldings_BUILD334_RELEASE.json
```

لا يعاد استخدام حزمة IPA المرشح القديمة بصمت. ملف التسليم المصحح ملف جديد ذو بصمة جديدة في مجلد إخراج جديد. تبقى تجربة التوقيع والترقية على حفظ المستخدم وجهازه الفعلي خطوة منفصلة.
